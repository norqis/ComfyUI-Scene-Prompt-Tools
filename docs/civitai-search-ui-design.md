# Civitai search, details and authentication

Search uses three desktop columns, two at intermediate widths and one on narrow screens, without horizontal scrolling. Cards preserve preview aspect ratios. Their footer shows a two-line model title, the actual updated date when provided, and model-level Downloads, Bookmarks and Likes. Missing or invalid counts display a dash; version statistics never substitute for model statistics.

Filters are Host, Base Model, Model Type, Category and Sort, below the query. Model types come from the public enums API in its original order. Category uses public model tags rather than an invented complete taxonomy. All omits the baseModels parameter. The four supported sorts are passed to the API unchanged; Updated and Published are not aliases for Newest.

Search and Detail share one modal. Back preserves the existing results DOM and scroll. Closing releases DOM, requests and observers. A WeakMap keyed by the actual node retains plain filter/result/scroll data for reopening within the page session, never DOM, nodes, graphs, requests, promises or full image metadata. A newer modal generation owns cache updates. This transient cache never enters workflow/node properties.

Eligible previews are public still images only, using the shared rating gate. Missing previews load only for visible cards, with at most three concurrent gallery requests and shared host/version promises. Failures are evicted for explicit Detail retry. Pagination is explicit, ordered and deduplicated. Image buttons open a child Civitai Image modal; Escape and overlay dismissal affect only the top modal, while programmatic parent dismissal cascades.

Image generation data is requested only after the public image API verifies the requested ID and preview eligibility. Generation parameters/resources take precedence over REST metadata, including its nested meta.meta form. Positive and negative prompts remain separate. Tags are shown only when explicitly published. Missing fields display the absence of public information. Large metadata objects become text only when expanded. No model loading, hash inventory or resource-by-resource lookup is needed to view details.

Model browsing is independent of file acquisition. Checkpoints, CLIP and other model types can be viewed without safetensors/hash requirements or local LoRA I/O. Only compatible, verified LoRA candidates offer acquisition. All derives the applicable model mode from the selected LoRA version, while preserving All as a search condition. Download re-fetches the authoritative model and verifies the selected file and SHA256 as before. Undo/redo and stale graph ownership remain intact.

Authentication is an explicit addition requested after the earlier anonymous-only design. Search, images, metadata, options and tags remain anonymous. The common Civitai authentication modal verifies an API key with Bearer GET /api/v1/me without redirects. It saves only after a positive integer ID and nonempty username are verified. Password/OAuth login is not part of this implementation.

Keys are stored atomically in each ComfyUI user's scene_prompt_tools/civitai_auth.json without encryption. GET/authentication/clear responses use no-store and never return the key. Concurrent verification has latest-request ownership; cancelled requests release temporary ownership. Clearing removes the local file, not the remote key. Keys are never saved to node properties, workflows, localStorage, URLs or logs.

Download snapshots the user's key without holding a lock during network I/O. Each redirect constructs fresh headers: Bearer is allowed only for exact HTTPS civitai.red/civitai.com origins using the default port without URL credentials, never CDN, HTTP or lookalike origins. Known login-required and creator-disabled responses receive distinct safe errors. Authentication-required errors open the same auth modal; successful authentication exposes a manual Re-download action and never downloads automatically.

Validation covers backend routes and normalization, user/secret isolation, cancellation and concurrent saves, redirected headers, browser responsive layouts, shared gallery requests, pagination, nested modal focus, injected text safety, missing metadata, authentication/retry, compact workflow serialization and actual isolated ComfyUI navigation. Production queues, models and GPU state are not part of these tests.
