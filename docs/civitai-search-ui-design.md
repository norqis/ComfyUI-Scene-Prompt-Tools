# Civitai search, details and authentication

Search uses six desktop columns, four at intermediate widths, two on narrower screens and one at the smallest width, without horizontal result scrolling. Cards preserve preview aspect ratios, show the model title directly below the image followed by the version, and use readable 14px text with 16px titles. The footer shows the base model on the left and the actual update date above one row of Downloads, Bookmarks and Likes on the right. Missing or invalid counts display a dash; version statistics never substitute for model statistics.

The query, Host, Base Model, Model Type, Category, Sort and search button share one non-wrapping toolbar, with horizontal toolbar scrolling when needed. Model types come from the public enums API in its original order. Category is a native select populated from official models_v9 category.name facets. Saved values remain during unauthenticated loading; after authentication, missing categories return to All. All omits the base-model filter. Sort order is Relevancy, Highest Rated, Most Downloaded, Most Liked, Most Collected and Newest. Relevancy omits the upstream sort parameter. Other sorts map to their official site index metrics or createdAt. Most Downloaded remains the default. Updated and Published are not aliases for Newest.

Search and Detail share one modal. Back preserves the existing results DOM and scroll. Closing releases DOM, requests and observers. A WeakMap keyed by the actual node retains plain filter/result/scroll data for reopening within the page session, never DOM, nodes, graphs, requests, promises or full image metadata. A newer modal generation owns cache updates. This transient cache never enters workflow/node properties.

Eligible previews are public still images only, using the shared rating gate. Missing previews load only for visible cards, with at most three concurrent gallery requests and shared host/version promises. Failures are evicted for explicit Detail retry. Pagination is explicit, ordered and deduplicated. Image buttons open a child Civitai Image modal; Escape and overlay dismissal affect only the top modal, while programmatic parent dismissal cascades.

Image generation data is requested only after the public image API verifies the requested ID and preview eligibility. Generation parameters/resources take precedence over REST metadata, including its nested meta.meta form. Positive and negative prompts remain separate text-only code blocks. Explicit public tags are non-interactive chips. Other metadata contains only scalar width, height, createdAt, seed, sampler, steps and cfgScale, in that order, with per-field null fallback and zero preserved. Workflow objects and all other metadata are excluded. Missing fields display the absence of public information. No model loading, hash inventory or resource-by-resource lookup is needed to view details.

Primary search uses one official site multi-search request with exact type, compatible base-model aliases and category filters. A single authenticated REST request hydrates only those model IDs with nsfw=true, retaining site ranking and omitting unrelated IDs. Preview eligibility remains unchanged. Missing REST collectedCount values are filled only from actual site collectedCount metrics; zero is preserved and favoriteCount never substitutes. Model browsing is independent of file acquisition. Checkpoints, CLIP and other model types can be viewed without safetensors/hash requirements or local LoRA I/O. Only compatible, verified LoRA candidates offer acquisition. All derives the applicable model mode from the selected LoRA version, while preserving All as a search condition. Download re-fetches the authoritative model and verifies the selected file and SHA256 as before. Undo/redo and stale graph ownership remain intact.

Authentication is an explicit addition requested after the earlier anonymous-only design. Searching civitai.red requires a saved user API key. Search sends Bearer only to the selected official host’s /api/search/multi-search and /api/v1/models endpoints. Missing or rejected authentication blocks search with an inline notice; saving a key enables manual search without starting it. civitai.com search uses the saved key when present and otherwise retains the server’s anonymous visibility. Image and detail lookups remain anonymous. Model-type enums are anonymous; category facets use the selected host’s search authentication. The common Civitai authentication modal verifies an API key with Bearer GET /api/v1/me without redirects. It saves only after a positive integer ID and nonempty username are verified. Password/OAuth login is not part of this implementation.

Keys are stored atomically in each ComfyUI user's scene_prompt_tools/civitai_auth.json without encryption. GET/authentication/clear responses use no-store and never return the key. Concurrent verification has latest-request ownership; cancelled requests release temporary ownership. Clearing removes the local file, not the remote key. Keys are never saved to node properties, workflows, localStorage, URLs or logs.

Download snapshots the user's key without holding a lock during network I/O. Each redirect constructs fresh headers: Bearer is allowed only for exact HTTPS civitai.red/civitai.com origins using the default port without URL credentials, never CDN, HTTP or lookalike origins. Known login-required and creator-disabled responses receive distinct safe errors. Authentication-required errors open the same auth modal; successful authentication exposes a manual Re-download action and never downloads automatically.

Validation covers backend routes and normalization, user/secret isolation, cancellation and concurrent saves, redirected headers, browser responsive layouts, shared gallery requests, pagination, nested modal focus, injected text safety, missing metadata, authentication/retry, compact workflow serialization and actual isolated ComfyUI navigation. Production queues, models and GPU state are not part of these tests.
Compatible LoRA Detail offers Acquire, opening a child destination picker immediately. The editable tree lists directories beneath the first configured LoRA root; blank means the root and direct relative paths create folders. Directory traversal excludes outside-root links and cycles, and sorts directories only. Acquire downloads and refreshes the local catalog without editing nodes or Undo history; Acquire and select explicitly applies the verified result. Auth retry preserves the chosen directory and action. Same-directory verified SHA matches reuse known files; another directory receives its own file. Temporary downloads are verified before atomic replacement. Directory listings and acquisition state are transient and never serialized into workflows.
