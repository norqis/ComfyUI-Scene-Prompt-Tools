# Civitai search, details and authentication

Search uses six desktop columns, four at intermediate widths, two on narrower screens and one at the smallest width, without horizontal result scrolling. Cards preserve preview aspect ratios, show the model title directly below the image followed by the version, and use readable 14px text with 16px titles. The base model appears at the image’s top left; the footer shows the author on the left and the actual update date above one row of Downloads, Bookmarks and Likes on the right. Missing or invalid counts display a dash; version statistics never substitute for model statistics.

The native Models/Users select precedes the query in the same non-wrapping toolbar, followed by Host, Base Model, Model Type, Category, Sort and search. Narrow toolbars scroll horizontally. Models remains the legacy/default mode; Users searches exact usernames through the existing models_v9 user.username filter with an empty full-text query, followed by the same single batch hydration. Blank Users queries omit the author restriction. Author buttons in Detail switch that same modal to Users and populate the query, preserving other filters. The search mode is transient cached UI state; legacy snapshots default to Models. Model types come from the public enums API in its original order. Category is a native select populated from official models_v9 category.name facets. Saved values remain during unauthenticated loading; after authentication, missing categories return to All. All omits the base-model filter. Sort order is Relevancy, Highest Rated, Most Downloaded, Most Liked, Most Collected and Newest. Relevancy omits the upstream sort parameter. Other sorts map to their official site index metrics or createdAt. Most Downloaded remains the default. Updated and Published are not aliases for Newest.

Search and Detail share one modal. Back preserves the existing results DOM and scroll. Closing releases DOM, requests and observers. A WeakMap keyed by the actual node retains plain filter/result/scroll data for reopening within the page session, never DOM, nodes, graphs, requests, promises or full image metadata. A newer modal generation owns cache updates. This transient cache never enters workflow/node properties.

Previews include every still image returned by the selected host, without local rating exclusions. Missing previews load only for visible cards, with at most three concurrent gallery requests and shared host/version promises. Failures are evicted for explicit Detail retry. Pagination is explicit, ordered and deduplicated. Image buttons open a child Civitai Image modal; Escape and overlay dismissal affect only the top modal, while programmatic parent dismissal cascades.

All provider-returned still-image previews are displayed regardless of rating fields; videos remain excluded. Gallery and image requests use browsingLevel=31 without an nsfw parameter, preserving both SFW and mature images. Image generation data is requested only after the image API verifies the exact requested ID and still-image type. Generation parameters/resources take precedence over REST metadata, including its nested meta.meta form. Positive and negative prompts remain separate text-only code blocks. Explicit public tags are non-interactive chips. Other metadata contains only scalar width, height, createdAt, seed, sampler, steps and cfgScale, in that order, with per-field null fallback and zero preserved. Workflow objects and all other metadata are excluded. Missing fields display the absence of public information. No model loading, hash inventory or resource-by-resource lookup is needed to view details.

Primary search uses one official site multi-search request with exact type, compatible base-model aliases and category filters. A single authenticated REST request hydrates only those model IDs with nsfw=true, retaining site ranking and omitting unrelated IDs. The selected host is used for search, details, gallery and image metadata without switching hosts. Image CDN URLs remain ordinary image requests without API keys. Missing REST collectedCount values are filled only from actual site collectedCount metrics; zero is preserved and favoriteCount never substitutes. Model browsing is independent of file acquisition. Checkpoints, CLIP and other model types can be viewed without safetensors/hash requirements or local LoRA I/O. Only compatible, verified LoRA candidates offer acquisition. All derives the applicable model mode from the selected LoRA version, while preserving All as a search condition. Download re-fetches the authoritative model and verifies the selected file and SHA256 as before. Undo/redo and stale graph ownership remain intact.

The common JSON transport authenticates every Civitai API request: searches, details, gallery/image metadata, generation data, descriptions, enums, tags and download metadata. Each operation snapshots the current ComfyUI user's saved key once. Explicit civitai.red requests require a key before HTTP; civitai.com uses a key when available and otherwise stays anonymous. Host-unspecified hash/description lookups skip red without a key. Authentication failures never become missing results, host fallbacks, optional dates or partial generation data. API redirects are disabled. Image CDN rendering remains ordinary public image delivery. Authentication enables manual retry, without automatically starting the failed operation. The common Civitai authentication modal verifies an API key with Bearer GET /api/v1/me without redirects. It saves only after a positive integer ID and nonempty username are verified. Password/OAuth login is not part of this implementation.

Keys are stored atomically in each ComfyUI user's scene_prompt_tools/civitai_auth.json without encryption. GET/authentication/clear responses use no-store and never return the key. Concurrent verification has latest-request ownership; cancelled requests release temporary ownership. Clearing removes the local file, not the remote key. Keys are never saved to node properties, workflows, localStorage, URLs or logs.

Download snapshots the user's key without holding a lock during network I/O. Each redirect constructs fresh headers: Bearer is allowed only for exact HTTPS civitai.red/civitai.com origins using the default port without URL credentials, never CDN, HTTP or lookalike origins. Known login-required and creator-disabled responses receive distinct safe errors. Authentication-required errors open the same auth modal; successful authentication exposes a manual Re-download action and never downloads automatically.

Validation covers backend routes and normalization, user/secret isolation, cancellation and concurrent saves, redirected headers, browser responsive layouts, shared gallery requests, pagination, nested modal focus, injected text safety, missing metadata, authentication/retry, compact workflow serialization and actual isolated ComfyUI navigation. Production queues, models and GPU state are not part of these tests.
Compatible LoRA Detail offers Acquire, opening a child destination picker immediately. The editable tree lists directories beneath the first configured LoRA root; blank means the root and direct relative paths create folders. Directory traversal excludes outside-root links and cycles, and sorts directories only. Acquire downloads and refreshes the local catalog without editing nodes or Undo history; Acquire and select explicitly applies the verified result. Auth retry preserves the chosen directory and action. Same-directory verified SHA matches reuse known files; another directory receives its own file. Temporary downloads are verified before atomic replacement. Directory listings and acquisition state are transient and never serialized into workflows.

The local LoRA picker combines its text search with an All/Illustrious/Anima/NoobAI/Pony base-model filter. It uses existing cached metadata; unknown visible rows resolve lazily and disappear individually if they do not match. Illustrious XL and NoobAI XL aliases match their respective families. Filtering does not change node settings.

The selection button always opens the local picker, including acquired files and saved workflows; the separate details button opens metadata. Verified acquisition metadata seeds the existing file-identity cache without another hash lookup. Pending, failed and genuinely unknown base models have distinct labels. Search cards highlight the actual selected local path, with provenance used only when that same path is selected.

Acquisition controls are disabled and gray during transfer. A final provider filename collision opens Cancel, Select only and Reacquire choices before writing the body. Select only uses the existing local file; if its SHA differs, only the LoRA path changes, leaving prompts, model mode and provenance untouched. Reacquire replaces only the confirmed destination after SHA validation; failures preserve its previous contents. File selections use native path separators while the acquisition manifest retains slash-separated relative names.

Acquired LoRA cards show a static `取得済み` badge at the preview top right, with the base model at top left in separate grid columns that cannot overlap. Detail keeps Back in its non-scrolling header during loading, errors and success. Search header authentication is hidden only while Detail is active; authentication transport and child error/retry controls remain unchanged. Ordinary Back restores the existing results DOM, scroll and focused card without another search. Standalone Civitai details return to local LoRA details; clicking an author closes those local details and opens the existing search with Users/query overrides.

Owned-file selection uses the existing batched SHA inventory result, now including the exact file revision. A fresh native catalog must contain the same path and revision before Select or Delete is offered. Select refreshes the native options, rechecks the graph/node/current LoRA after the await, applies its actual native separator spelling in one Undo transaction and injects no triggers. Positive and negative prompts stay byte-for-byte unchanged. It performs no download, new hash lookup or model loading. Files owned only through a hidden root have no selectable path. Late ownership updates only existing buttons and badges without rebuilding Detail or moving focus.

Local LoRA details offer a red Delete button from catalog information even while external metadata is loading or unavailable. Civitai Detail offers Delete for the verified local file. A shared confirmation displays the relative path and explains that filesystem deletion cannot be undone. Cancel makes no request. Confirm posts `{name, file_revision}` to `/scene_prompt/loras/delete`; stale revision/root mappings return 409, missing files 404 and invalid requests 400. The owner and confirmation stay busy until completion. The backend deletes exactly the resolved file under its existing per-file lock, refuses leaf symlinks, and leaves sidecars, directories, alternate copies and loaded models alone. Successful deletion refreshes the native catalog and prunes metadata, marks Detail deleted and rechecks ownership. The current LoRA name remains visible with an explicit deleted warning; prompt values, provenance and graph Undo history do not change.
